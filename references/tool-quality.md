# 自建工具的验收标准

> 写完一个脚本/自动化，不要只测成功路径。以下每条都是踩过的坑。

## 八条硬标准

| # | 标准 | 怎么验 |
|---|---|---|
| 1 | **幂等** | 连跑两次，第二次必须零改动（noop 计数 = 全部） |
| 2 | **漂移可见** | 故意写坏一个文件，工具必须报出来，不能默默通过 |
| 3 | **dry-run 可用** | `--check` 只读不写，可用于审计与 CI |
| 4 | **不擅自覆盖** | 修改前先备份（`.bak.<时间戳>`），用户数据优先于"修好" |
| 5 | **并发安全** | 两个实例同时跑，一个必须被挡住（锁） |
| 5b | **锁原语一致性** | 多层锁**不能运行时降级**，否则持有不同原语的进程互相看不见；必须按环境预先单一确定 |
| 5c | **陈旧锁可回收** | 持有者崩溃后，锁必须能靠 pid 判活 + 租约被回收，否则系统永久卡死 |
| 6 | **退出码有意义** | 0 绿 / 2 漂移 / 3 锁占用 / 4 用法错 / 5 锁不可用，写进文档 |
| 7 | **写操作原子** | 临时文件 + rename，避免读者读到半截 |
| 8 | **性能有基线** | 预热 + 中位数 + MAD 剔异常；只做同时段 A/B；<10% 收益不加复杂度 |

## 安全三条（共享环境下必做）

| 风险 | 防护 |
|---|---|
| **路径穿越**：`../../x` 把文件写到允许范围之外 | 路径规范化后**白名单校验**（只允许 workspace / shm / tmp） |
| **符号链接写穿**：目标文件被换成指向别处的链接 | 写入前 `[ -L ]` 检测，命中即**拒绝并报错**，不静默 unlink |
| **TOCTOU**：检查与使用之间被替换 | 关键路径用一次判定，不做"先查后用"的两次 stat |

## 输出分离

- **诊断信息走 stderr**（`[FAILED]` / `[refuse]` / `[busy]`）
- **结构化报告走 stdout**（对账摘要、统计）
- 这样用户能 `script > out.txt` 而不混入日志

## 测试隔离：别拿真实系统文件当靶子

测试安全逻辑时，**绝不要操作真实系统文件**。业界标准做法是用无害的"假靶子"：

| 借用 | 来源 |
|---|---|
| 临时目录/文件 fixture，用完自动清理 | pytest 官方 `tmp_path` 实践 |
| 测杀毒软件不用真病毒，用**无害假样本** | EICAR 标准测试文件（业界通用） |
| 沙箱是隔离环境，不影响真实系统 | Stripe 沙箱文档 |

**收益是双向的**：
1. 测试不会因误操作破坏真实环境（安全）
2. 也不会被平台内容审核误判为危险操作（可发布）

**结论**：假靶子不是"绕过审核的取巧"，而是本来就该这么写。用真实系统文件做测试靶子，本身就是测试设计缺陷。

## 重试与退避（对外部调用）

| 规则 | 说明 |
|---|---|
| **只重试可重试的** | 4xx（除 408/429）不重试——重试也不会成功；5xx / 超时 / 429 才重试 |
| **指数退避** | `delay = base × 2^attempt`；线性不够，会让竞争客户端同时失败 |
| **加 jitter** | 全抖动打散，避免惊群造成二次洪峰 |
| **设上限** | capped（如最大 30 秒），防无限等待 |
| **限次数** | 3–5 次后放弃并明确报错，不无限重试 |
| **幂等前提** | 只有幂等操作才可重试；非幂等（如扣款）重试会重复执行 |

## 测试怎么写

- 写成断言脚本（`selftest.sh`），不写一次性命令
- 每条标准一个断言，全绿才算过
- 破坏性测试放独立目录（`/dev/shm` 最快，且不污染真实数据）
- 断言统一写法：`out=$(cmd); echo "$out" | grep -q ...`（不要用管道直接进 if 条件）

## 评测集（回归集）

业界推荐技能/agent 的黄金数据集规模为 **50–200 件**（Anthropic 实践）。
本技能的 `selftest.sh` 24 项断言是**最小回归集**，规则：

1. **每发现一个新缺陷，先加一条断言复现，再修**——顺序不能反
2. 断言只增不删（除非对应机制整体移除）
3. 每次改机制必须全量跑，全绿才交付
4. 总数超过 50 后按模块拆成多个测试文件
5. 定期把生产/实战中的失败案例回流成新断言
