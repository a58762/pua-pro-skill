# 记忆设计：分层、懒加载、可恢复

## 为什么需要分层

单一记忆文件会随时间膨胀，最终两个问题同时出现：主文件被杂信息淹没（核心流程读不清），以及每次会话都全量加载（token 浪费、注意力被稀释）。

国外主流方案都走分层：
- **短期 / 长期 / 临时**三分（Google ADK 实践）
- **`system/` 目录自动载入，其余按需读取**（Letta MemFS）
- **版本化文件系统，支持跨会话恢复与推理迁移**（Git Context Controller, arXiv 2508.00031）

## 本技能的分层

| 层 | 位置 | 生命周期 | 何时加载 |
|---|---|---|---|
| 系统层 | `.pua/system/always.md` | 长期，改动少 | 每次会话开头 |
| 基线层 | `.pua/memory/evolution.md` | 长期，只升不降 | 每次会话开头 |
| 教训层 | `.pua/memory/anti-patterns.md` | 长期，只增 | 每次会话开头（扫相关项） |
| 项目层 | `.pua/memory/project.md` | 中期 | 遇到相关任务时 |
| 技能层 | `.pua/skills/index.md` + 条目 | 长期，缓慢增长 | 索引每次读，正文按需 |
| 工作层 | `.pua/journal.md` | 短期，<2h 有效 | 仅在恢复时 |

## 各层写什么

**system/always.md**（≤ 30 行）
- 当前身份定位、不可违背的硬约束、口味偏好
- 不写项目细节，不写历史

**memory/evolution.md**
- 性能统计、当前基线、已内化模式
- 判据必须是**行为**（"先读源码再判断"），不是结果（"做得很好"）

**memory/anti-patterns.md**
- 一条三行：现象 / 根因 / 下次怎么做
- 上限约 50 条；超过后合并同类项，保留高频的

**memory/project.md**
- 构建/测试/部署命令、已知陷阱、路径约定
- 不记凭据、不记临时状态

**skills/index.md**
- 一行一条：名字 | 前提 | 验证 | 边界
- 索引只放元信息，正文另存

## 写入纪律

1. **写完必须回读一行确认**（不是写完就算完）
2. **不写"应该是"**——写入的都是确认过的事实或教训
3. **不写第三人称八卦**——只记任务相关的技术与偏好
4. **不做无意义追加**——同一教训已在文件里就不重复写

## 测量方法学（2026-11-23 修正，优先读这节）

**教训**：上一版数字用 5–10 次取平均、无预热、无异常剔除，**不可信**——同一脚本两次测量差 4 倍。

**正确方法**（依据 hyperfine 与日本社区计数法）：
1. 预热 3 次，再测 20 次
2. 报告**中位数**，不报均值（均值被异常值污染）
3. 用 **MAD（中位数绝对偏差）** 剔除偏离 >3.5 MAD 的异常
4. 短命令给**吞吐（次/秒）**，不要只给单次毫秒
5. **绝对耗时不可跨时段比较**，只有同一时段的 A/B 对比可信

工具：`scripts/bench.py "<命令>" [次数]`

**重测结果（同时段 A/B，脚本放 /dev/shm）**：

| 版本 | median | 吞吐 |
|---|---|---|
| 每文件 `grep` + `wc`（2 次 fork） | 494 ms | 2.0 次/秒 |
| `mapfile` 内建（1 次 open） | **298 ms** | **3.3 次/秒** |

→ 提升 **40%（1.66×）**，三轮独立复现一致。

**附带发现**：
- 脚本文件放 fuse 上，每次启动多花约 97 ms（366 → 269）
- 纯 `bash -c true` 启动仅 4.1 ms

## IO 性能实测（早期数据，方法不严谨，仅作量级参考）

| 操作 | fuse（`/sandbox/workspace`） | 内存盘（`/dev/shm`） |
|---|---|---|
| 写 1 个小文件 | ~200 ms | ~12 ms |
| `mkdir -p` 3 个目录 | ~265 ms | ~15 ms |
| 全新初始化（建目录 + 写 4 文件） | 1950–3000 ms | ~51 ms |
| 稳态对账（读 4 文件 + 锁） | ~98 ms | ~10 ms |
| 并行写 4 文件 vs 串行 | 692 vs 772 ms（仅 +10%） | — |

**结论**：
1. **可丢弃的高频状态**（测试目录、锁文件、心跳、临时检查点候选）放 `/dev/shm`，比 fuse 快 10–60 倍。
2. **必须持久的状态**留 `workspace`，接受一次性初始化成本（约 2–3 秒，仅在首次/重置后发生）。
3. **不要为并行而并行**：4 文件并行写只省 10%，复杂度不值得。
4. **稳态 98ms 已到感知阈值以下**，不必再抠 40ms——那是边际收益趋零的区域。

## 版本化（可选但推荐）

若需要回溯，`.pua/` 可纳入 git：

```
cd /sandbox/workspace/.pua && git init && git add -A && git commit -m "baseline"
```

好处：能看到基线是怎么一步步抬上去的；坏处：频繁 commit 会拖慢。建议每完成一个主要任务 commit 一次，而不是每次写入。

## 反例（别这样做）

- ❌ 把所有内容塞进一个 `memory.md`
- ❌ 每次会话全量加载所有技能正文
- ❌ 把历史对话原文抄进记忆（应提炼成教训）
- ❌ 基线用"感觉做得不错"这种无法判定的描述
